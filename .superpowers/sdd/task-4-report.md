## Fix-раунд (ревью координатора, 2026-08-23)

Ревью вернуло 5 замечаний по `src/food.ts`. Правки — только в `src/food.ts` (плюс новый
`src/food.test.ts`), `src/router.ts` не трогала.

1. **Изоляция по элементу.** Тело цикла обёрнуто в `try/catch`; при любой ошибке (поиск, сервинги,
   LLM, парсинг) — `logError('food-match', error)` и в результат уходит запись с
   `food: null, servingId: null, units: 0, grams: null, calories: null,
   note: 'ошибка подбора — попробуй ещё раз'`. Один плохой item больше не роняет весь батч.
2. **Несовпадение food/serving.** Кандидаты обрезаются до топ-3 (`found.slice(0, 3)`), сервинги
   тянутся для всех трёх параллельно (`Promise.all`), в LLM уходит один вызов с массивом
   `{food, servings}[]` на кандидата. Модель обязана вернуть пару из одного и того же кандидата;
   `pickValidPair` проверяет это (foodId ∈ топ-3 И servingId принадлежит именно ему), при
   несовпадении откатывается на первого кандидата с непустыми сервингами (не жёстко на
   `candidates[0]` — у него сервингов может не быть).
3. **Пустые сервинги.** Если у ВСЕХ трёх кандидатов сервингов нет — `food: null,
   note: 'не нашла порций в базе'`, LLM не вызывается (проверено тестом: флаг `called` остаётся
   `false`).
4. **Валидация чисел от модели.** `units` — санитайзится диапазоном `(0, 50]`: невалидное (не число,
   ≤0, >50) → откат на `1`. `grams` — если не конечное положительное число → `null`. Проверка не в
   zod (`matchSchema` пропускает вход по типу `number`/`number|null`), а отдельными функциями
   `sanitizeUnits`/`sanitizeGrams` — так же, как в `pickValidPair`, ошибка не роняет item, а даёт
   безопасный дефолт.
5. **Тесты — `src/food.test.ts` (новый файл), DI без мока модулей.** `matchFoodItems` получил
   необязательный второй параметр `deps: MatchFoodDeps` (`searchFoods`/`getServings`/`chooseFood`,
   по умолчанию — реальные `fsSearchFoods`/`fsGetServings`/`chooseFoodAndServing`); публичная
   сигнатура для Task 5/6 (`matchFoodItems(items)`) не изменилась, только добавился опциональный
   аргумент. 7 тестов: пустой поиск → `не нашла в базе`; калории = `serving.calories × units`;
   ошибка первого item не мешает второму (изоляция); невалидная пара food/serving → откат на первого
   кандидата с сервингами; все кандидаты без сервингов → `не нашла порций в базе` без вызова LLM;
   units вне диапазона → откат на 1.

Добавлен комментарий в коде (единственный по-настоящему неочевидный момент) — почему сервинги тянутся
для топ-3 кандидатов, а не одного: первый по релевантности поиска не всегда правильный продукт
(бренд, другой вид блюда), и без сервингов остальных двух модели не из чего реально выбирать.
