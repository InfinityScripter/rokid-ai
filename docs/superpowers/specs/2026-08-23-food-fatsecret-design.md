# Еда → дневник FatSecret (этап 4) — дизайн

Дата: 2026-08-23. Статус: дизайн утверждён в диалоге, ждёт ревью текста.

## Решение

Дневник еды живёт **только в FatSecret** — это основа этапа, локального
дневника как продукта нет. Бот распознаёт еду по фото и голосу с очков,
показывает карточку подтверждения в Telegram и после явного «Записать»
пишет приёмы пищи в дневник пользователя через FatSecret API. Смотреть
итоги (КБЖУ, история, графики) пользователь будет в приложении FatSecret.

Отклонённые альтернативы: локальный дневник с зеркалом в FatSecret
(пользователь выбрал FatSecret как единственное хранилище); ожидание
одобрения Premier Free без разработки (теряем недели); «распознали —
вбей руками» (не автоматизация).

## Ограничение, принятое осознанно

И Basic, и Premier Free дают **только американскую базу продуктов**
(58 стран и 26 языков — лишь в платном Premier). Русские блюда ищем
по английским названиям (роутер уже умеет переводить), локальных брендов
не будет. Компенсация — карточка подтверждения: пользователь видит
подобранный аналог до записи.

## Архитектура

Новый модуль `src/fatsecret.ts` — единственная точка работы с API:

- OAuth 2.0 client-credentials токен (кэш в памяти до истечения) для
  поиска: `foods.search` (v3), `food.get` (порции и КБЖУ вариантов).
- OAuth 1.0 3-legged для дневника: `food_entry.create`,
  `food_entry.delete` (для отката и тестов). Подпись HMAC-SHA1 пишем
  сами (~30 строк, без новых зависимостей).
- Одноразовая связка аккаунта: команда `/fatsecret_link` в боте — бот
  выдаёт ссылку авторизации, пользователь жмёт «разрешить», присылает
  PIN (oob-flow), токены сохраняются в файл рядом с очередью
  (`*.fatsecret.json`). Делается один раз.

Поток (расширение существующего конвейера `food_log`):

1. Фото → `parseFoodPhoto` / голос → `routeText` — уже работают, отдают
   список «продукт + порция словами».
2. Для каждого продукта: перевод названия на английский (роутер уже
   возвращает по-русски → добавляем английское поле `query` в интент),
   `foods.search` → топ-кандидаты → LLM выбирает продукт и переводит
   порцию в граммы/сервинги (`food.get` для точных порций).
3. Карточка в Telegram: «продукт → аналог из базы, граммы, ккал»,
   сумма КБЖУ, кнопки «✅ Записать» / «✏️ Поправить» / «❌ Не надо».
   Приём пищи — по времени в Москве (уже реализовано для фото).
4. «Записать» → `food_entry.create` на каждый продукт → ответ со ссылкой
   «смотри в приложении FatSecret» и подписью powered by fatsecret.
5. «Поправить» → пользователь отвечает текстом/голосом («борщ 400,
   тосты убери») → пересборка карточки.

## Период до одобрения Premier Free

Поиск и карточки работают сразу (Basic это разрешает). Подтверждённые
карточки складываются в буфер отправки на VDS (тот же JSON-механизм, что
очередь рабочих событий) и автоматически доливаются в дневник задним
числом после одобрения — `food_entry.create` принимает дату. Это буфер,
а не второй дневник: никакой читалки по нему не строим.

## Ошибки

- Поиск ничего не нашёл → продукт попадает в карточку с пометкой
  «не нашла в базе» и в дневник не пишется; остальные пишутся.
- API вернул ошибку записи → карточка остаётся с кнопкой «Повторить»,
  запись не теряется (буфер).
- Просрочка/отзыв OAuth-токенов → бот честно просит перепривязать
  аккаунт командой `/fatsecret_link`.

## Проверка

Тестовой инфраструктуры в проекте нет. Проверяем живыми прогонами:
- поиск: реальные фразы («борщ», «два тоста с сыром») → осмысленные
  кандидаты с КБЖУ;
- запись (после одобрения): тестовая запись в дневник → видна в
  приложении FatSecret → `food_entry.delete`;
- полный путь: фото еды в бота → карточка → «Записать» → запись в
  приложении.
