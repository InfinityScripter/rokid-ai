# Саммари встреч (этап 5, v1) — дизайн

Дата: 2026-08-26. Статус: реализовано вместе со спекой (v1).

## Решение

Запись встречи приходит в Telegram-бот голосовым или аудиофайлом. Всё, что
длиннее 3 минут (`MEETING_AUDIO_THRESHOLD_SECONDS`), — встреча: вместо
разбора намерения запись уходит в конвейер саммари и бот отвечает готовым
саммари (тема, главное, решения, задачи). Короткие записи работают как
раньше — через роутер намерений.

Отклонённые альтернативы v1: хранение расшифровок и саммари в файлах/базе
(некуда смотреть, Telegram-чат и есть архив); запись встреч с очков (клиент
пока не шлёт длинные записи — офлайн-очередь очков остаётся в бэклоге);
диаризация «кто говорил» (Gemini/Whisper без диаризации, не выдумываем).

## Архитектура

Новый модуль `src/meeting.ts`:

- `transcribeLong(audioPath)` — ffmpeg режет запись на куски по 5 минут
  (`-f segment`, перекодирование в mp3 48 кбит/с моно), каждый кусок идёт в
  существующий `transcribe()` из `src/stt.ts`, тексты склеиваются. Резать
  обязательно: у пути через OpenRouter (VDS) выход ограничен 2048 токенами
  на вызов — час записи в один вызов не помещается; whisper-cpp на Маке
  куски тоже переваривает.
- `splitTranscript(text, maxChars)` — чистая нарезка длинного текста по
  границам строк/предложений (покрыта тестами). Используется и для
  map-reduce саммари, и для отправки длинных ответов в Telegram (лимит
  сообщения 4096 символов).
- `summarizeMeeting(transcript)` — расшифровка короче ~24k символов →
  одно саммари одним вызовом LLM (`ROUTER_MODEL`); длиннее — map-reduce:
  тезисы по каждому куску, затем финальное саммари по тезисам.

`src/bot.ts`: ветка «запись длиннее 3 минут» вместо отказа ведёт в
`handleMeetingAudio` — статусный ответ, скачивание, `transcribeLong`,
`summarizeMeeting`, ответ (длинный — частями). Интент `meeting_audio`
(голосом «сделай саммари» без записи) отвечает подсказкой прислать запись.

## Ограничения, принятые осознанно

- Лимит Telegram Bot API на скачивание файла — 20 МБ: голосовые (~1 МБ/мин)
  проходят ~20 минут, длинные аудиофайлы — если ужаты. При превышении бот
  честно называет лимит и просит ужать (mp3 48 кбит/с ≈ 3 часа в 20 МБ).
- Расшифровка после саммари не хранится и не отправляется: v1 отдаёт только
  саммари. Понадобится полный текст — отдельный пункт бэклога.
- Куски расшифровываются последовательно: на VDS одно ядро, параллельные
  вызовы Gemini упираются в rate-limit, а выигрыш минуты не стоит гонок.

## Ошибки

- Пустая расшифровка (тишина/шум) → честное «не разобрала запись».
- Файл больше лимита Telegram → сообщение про 20 МБ и как ужать.
- Ошибка LLM/ffmpeg → `logError('meeting')` + текст ошибки в чат.

## Проверка

- `splitTranscript` — юнит-тесты (границы, жёсткий рез, целостность текста).
- Живой прогон после деплоя: голосовое 5+ минут в бот → саммари с темой и
  пунктами; аудиофайл часовой встречи (ужатый) → саммари через map-reduce.
